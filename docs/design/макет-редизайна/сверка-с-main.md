## Достижения: что готово в коде, чего не хватает

Общий вывод: готов только сырой учёт просмотров (по видео, без дат) и обычные данные тестов/конспектов/вопросов с датами. Хранилища наклеек, подсчёта, наборов, пометок «предыдущий набор» и «поток переподготовки» нет.

### Что есть в данных (с путями)

- Просмотры по видео: `users/{uid}/courseProgress/{courseId}.videoStats.{lessonId}.{videoKey}` = `{ watched, openedExternally, spans[], duration }` (`src/lib/courseProgress/types.ts`, запись `src/lib/courseVideoStats.ts`, схема `docs/reference/firestore-schema.md:174–181`). Порог 60% реально проигранных минут, не 80%. Даты просмотра нет; есть `updatedAt` на документе курса (`cloudSync.ts`), он перезаписывается при любом сбросе. `videoKey` — YouTube id или `url-<хэш>`.
- «Главная лекция»: `watchedLessonIds[]` (первое видео секции «Видео-лекция»/«Видео»); старые отметки (до 30.09) трактуются так же.
- Основные видео занятия: `collectLessonVideoKeys` / `collectLessonDocVideoKeys` (`src/features/periods/utils/lessonVideos.ts`). «Дополнительные видео» исключены из учёта.
- Админская сводка: `getCourseStudents` + `src/lib/courseVideoStats.ts`, `src/pages/admin/students/studentViews.ts` считают лекции X/N и «Все видео Y/M (P%)», квадратики. Доступно только админу курса через callable; для студента готового расчёта «пройдено занятий / курс» нет, кроме процента на /home (`homeHelpers.ts`, «процент по реальному списку занятий с пересечением отметок», `dc9a1d58`).
- Тесты: `testResults/{id}` — `userId, testId, score, totalQuestions, answers[], completedAt` (`firestore-schema.md:712`). Поле `passed` в схеме «score === totalQuestions», а порог (70/75/80%) — в `tests.requiredPercentage`. Дата и лучший результат считаются на клиенте (`groupResultsByTest` в `src/lib/testResults.ts`, `bestPercentage`). Цепочки уровней: `prerequisite` + порог следующего теста (`074cf876`).
- Конспекты: `notes/{id}` с `noteScope: 'lecture'`, `visibility: 'private'|'group'|'lecturers'`, `createdAt/updatedAt`, `courseId`, `periodId`, `lectureKey` (`firestore-schema.md:506`). Это живой «открытый» конспект: «поделился» — это текущее значение `visibility`, а не событие.
- Вопросы: `lectureQuestions/{id}` с `authorUid, courseId, periodId, videoId, visibility, createdAt` (`firestore-schema.md:557`). Читать можно владельцу, лекторам и группе; запрос «мои вопросы» по `authorUid` — возможен клиентом.
- Телеметрия `feature_events` (PT-1): есть события `lecture_question_asked`, `note_shared`, `test_started`, `test_completed`, но с `hashedUid` (SHA-256, 16 символов) и дедупликацией по сессии (`docs/guides/product-telemetry.md`). Для персональных наклеек непригодна (анонимна, неполная, только прод).
- Роли/доступ: `courseAccess` в `users/{uid}`, группы `memberIds`, `grantedCourses`, `featuredCourseIds`, эффективный доступ через группы (`af0584f0`). Набор «Старт/Курс» определяется по ним; «Программа» — нет (см. ниже).
- `users.lastLoginAt` (`src/types/user.ts:84`) — перезаписывается, истории входов нет.

### По группам наклеек из `наклейки-предложение-v2.md`

1. За лекции и занятия («Ну, поехали!», «Я хочу разобраться», «Вошли во вкус», «10 занятий спустя»).

   - Нет: дат просмотра; «Пересмотрели лекцию» невозможна: после `watched=true` отрезки не пишутся (`courseVideoStats.ts`, «статус окончательный»), счётчика просмотров нет.
   - Нет: пометки «предыдущий набор» для правила «занятие = все видео, кроме прошлого набора»; текущее правило кода — только главная лекция.
2. За курсы («Основа основ», «Вся жизнь целиком» и т. д., «Курс пройден»).
