# Продуктовая телеметрия

Два контура, оба со сводкой в **`/superadmin/telemetry`** (только super-admin):

- **PT-1 — использование фич**: какие фичи студенты реально трогают, какая доля
  учебных сессий мобильная. Только авторизованные.
- **PV-1 — посещения страниц** (раздел ниже): сколько людей заходит на лендинги,
  включая гостей; когда заходят, докуда скроллят, кликают ли CTA.

## Куда смотреть

Сводка: **`/superadmin/telemetry`** (только super-admin). Три блока:

- карточки: событий за период, уникальных пользователей, доля мобильных событий;
- таблица «События × недели» — счётчики по неделям (колонка = понедельник недели)
  плюс строка уникальных пользователей по неделям;
- таблица «Split mobile / desktop» по каждому событию.

Диапазон — 4/12/26 недель (по умолчанию 12). Агрегация на клиенте: сводка
читает сырые документы `feature_events` напрямую (без API), объёмы первых
месяцев это позволяют.

## Как читать цифры

Главное: **события дедуплицируются в рамках сессии** (вкладки браузера) по ключу
`event + courseId + periodId`. Счётчик означает «в стольких сессиях фичу
использовали», а не «столько раз кликнули». Это устойчивее к power users и
прямо отвечает на вопрос «используется ли фича вообще».

Следствия:

- «Тест начат» на разных занятиях одного курса в одной сессии = 1 событие
  (meta теста — только `courseId = test.course`).
- Повторные research-поиски в сессии = 1 событие `research_search`.
- Соотношение `test_completed / test_started` — грубая воронка доведения теста
  до конца (в рамках сессий, не попыток).

Прочие ограничения выборки:

- пишут только **авторизованные** пользователи и только **с прода**
  (`import.meta.env.PROD`): гости и dev-сессии в статистику не попадают;
- телеметрия fire-and-forget: сбой записи молча теряет событие (это осознанно —
  сбой никогда не влияет на UX), цифры — оценка снизу;
- `platform` определяется по `matchMedia('(pointer: coarse)')` — это тип
  устройства (тач), а не ширина окна; фолбэк — `desktop`.

## Словарь событий (v1)

| Событие | Где размечено |
|---|---|
| `study_mode_opened` | `VideoSection.tsx` — переход в режим «Видео + заметки» |
| `transcript_opened` | `VideoStudyOverlay.tsx` — правая панель переключена на транскрипт |
| `selection_explain` | `useLectureExplain.ts` — «Объяснить» в selection-меню транскрипта |
| `selection_search` | `VideoTranscriptPanel.tsx` — «Статьи» в selection-меню |
| `research_search` | `useResearchSearch.ts` — запуск поиска статей |
| `book_rag_question` | `useBookAnswer.ts` — вопрос по книгам (RAG) |
| `lecture_ai_question` | `useLectureAnswer.ts` — вопрос лекционному AI |
| `lecture_question_asked` | `AskLectureQuestionModal.tsx` — вопрос лектору отправлен |
| `note_shared` | `ShareLectureNoteModal.tsx` — конспект отправлен группе/лекторам |
| `test_started` | `useTestProgress.ts` — клик «Начать» на интро-экране теста |
| `test_completed` | `useTestProgress.ts` — тест дошёл до финального экрана |

Новое событие = новая строка в `FeatureEventName` (`src/lib/telemetry.ts`) +
вызов `trackFeatureEvent` в точке использования. Rules валидируют только ключи
и длины полей, словарь событий не хардкодят — деплой rules при добавлении
события не нужен.

## Механика

- Схема и rules: [firestore-schema.md → feature_events](../reference/firestore-schema.md#продуктовая-телеметрия);
  регрессионные rules-тесты — `tests/integration/firestoreRules.test.ts`
  (блок `feature_events`), юнит-тесты helper'а — `src/lib/telemetry.test.ts`.
- `hashedUid` = SHA-256(uid), hex, усечённый до 16 символов — деанонимизация
  сводкой невозможна, тексты запросов/заметок не сохраняются.
- Запись — `addDoc` напрямую в Firestore с клиента (никакого API-слоя,
  инвариант лимита Vercel-функций). Composite-индексы не нужны: сводка
  фильтрует только по `createdAt` (одиночное поле, автоиндекс).
- Объёмы: десятки событий в день при free tier 20k writes/день — запас ×100+.

## Ретеншн (отложен)

До первых данных сырые события не чистятся. Кандидаты (зафиксированы в
`docs/processes/audit-backlog.md`, PT-1): месячная агрегация + чистка шагом
существующего weekly job `functions/src/weeklyTranscriptRefresh.ts` (это
functions deploy — отдельное одобрение), либо Firestore TTL-политика на поле
`createdAt` (включается в консоли/gcloud, кода не требует).

## Телеметрия посещений страниц (PV-1)

Считает посещения публичных лендингов **включая гостей**. Выбрана вместо
Яндекс.Метрики/Clarity осознанно: данные посетителей не уходят третьим сторонам
(контекст — психологическая платформа), блокировщики рекламы запись не режут.
Цена размена: нет пиксельных тепловых карт кликов и записей сессий — вместо них
агрегированный scroll-depth и счётчики кликов по размеченным CTA.

### Что видно в сводке

Раздел «Посещения страниц» в `/superadmin/telemetry`:

- карточки: просмотры, уникальные (гости / с аккаунтом), новые посетители,
  записи телеметрии за месяц с процентом от потолка, **гипотетическая стоимость
  в месяц** (сколько бы стоило по прайсу Firestore без бесплатных квот;
  фактически $0, пока объёмы в квотах);
- таблица по страницам; тепловая карта «день недели × час» (локальное время
  посетителя); глубина скролла (доля просмотров, дочитавших до 25/50/75/100%);
  клики по CTA.

### Механика и семантика цифр

- Ядро — `src/lib/pageVisits.ts`; единая точка — хук `usePageVisitTracking`
  в `AppShell` **до** ветвления `isStandaloneLanding` (лендинги рендерятся
  отдельной веткой, хук ниже ветвления их бы не видел).
- **Добавить страницу = одна строка** в `TRACKED_PAGES` (`src/lib/pageVisits.ts`);
  деплой rules не нужен. Разметить клик = атрибут `data-track-click="id"` на
  элементе.
- Privacy-first: на сервер уходят только инкременты агрегатов
  (`page_visit_daily`, схема — [firestore-schema.md](../reference/firestore-schema.md#page_visit_dailypageid__date-pv-1));
  идентификаторов посетителя нет. «Уникальный за день» и «новый посетитель» —
  локальная отметка в localStorage: почистил браузер / другое устройство =
  новый уникальный, т.е. цифры уникальных — оценка сверху, просмотров — снизу
  (боты, исполняющие JS, не фильтруются; fire-and-forget теряет события молча).
- Гость/с аккаунтом определяется после первого `onAuthStateChanged`.
- Scroll-depth уходит одной записью при сворачивании вкладки или уходе со
  страницы (max-глубина за просмотр); клики дедупятся в рамках просмотра.
- Пишется только с прода (`import.meta.env.PROD`).

### Автостоп (потолок записей)

`MONTHLY_WRITE_CAP = 100_000` записей/месяц (`src/lib/pageVisits.ts`) — при
достижении клиент молча перестаёт писать до 1 числа следующего месяца; сводка
показывает красную плашку. Проверка — одно публичное чтение
`page_visit_months/{YYYY-MM}` на сессию (кэш в sessionStorage). Потолок —
клиентский: защищает от органического перерасхода, не от злонамеренного спама
(тот ограничен формой данных: инкременты ≤5 за запись, стоимость мусорного
миллиона записей ≈ $1.8).
