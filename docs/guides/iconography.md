# Иконография: бесплатный публичный портал

Статус: проверенная локальная версия, 2026-09-09. Production-публикация отдельно согласуется с владельцем. Пользователь разрешил реализацию после оценки стоимости; публикация и облачные аккаунты не создавались.

## Маршруты и переиспользование

`/iconography/*` — самостоятельный публичный раздел без регистрации. `src/pages/IconographyPage.tsx` загружается через `src/pages/lazy.ts` и общий `Suspense` / `PageLoader`. `AppShell` использует существующую ветку `StandaloneLandingShell`, без загрузки курсов. В общей сборке сохраняется глобальная инициализация Auth Академии; каталог и прогресс сами не обращаются к Firestore.

| Путь | Назначение |
| --- | --- |
| `/iconography` | Сразу викторина по узнаваемым храмовым образам, до семи икон за занятие |
| `/iconography/catalog` | Поиск, фильтры традиции и века, страницы по 12 записей |
| `/iconography/icon/:id` | Изображение, полный паспорт, признаки, источники, комментарий |
| `/iconography/practice` | Тренировка параметра, одного произведения, повторение |
| `/iconography/compare` | Два произведения рядом, пять подготовленных пар, произвольный выбор |
| `/iconography/learn?step=0` | Четыре наблюдения на иконах Кирилло-Белозерского иконостаса, его четырёхрядная схема |
| `/iconography/schools/:id` | Статья о школе/традиции, источники и связанные примеры |
| `/iconography/about` | Принципы отбора, источники, ограничения |
| `/iconography/support` | Добровольная поддержка без реквизитов до их подтверждения |

Параметры URL: `q`, `tradition`, `century`, `page` в каталоге; `left`, `right` в сравнении; `icon`, `topic`, `repeat=1` в практике. Фильтры доступны по прямой ссылке. `Practice` имеет ключ по query string, чтобы переход к повторению действительно создавал новое занятие.

## Данные и расширение каталога

- `public/iconography/catalog.json` — компактный поисковый индекс, загружается только после входа в портал; не импортируется в JS.
- `public/iconography/schools.json` — 12 коротких статей; загружаются при входе на страницу школы. `schoolId` в индексе связывает примеры, не уточняя спорную атрибуцию.
- `public/iconography/records/*.json` — независимые полные паспорта и задания. Загружаются по требованию, кэш ограничен 40 записями.
- `public/iconography/images/*.webp` — 320 / 800 / 1600 пикселей по ширине, без увеличения исходников.
- `scripts/iconography/media-manifest.json` — источник, лицензия, авторство репродукции, дата проверки, SHA-256 скачанной музейной копии.
- `VITE_ICONOGRAPHY_ASSET_BASE` — необязательный базовый HTTPS-адрес каталога и медиа, по умолчанию `/iconography`. При переносе нужны CORS для JSON и та же структура файлов. Не использовать URL с секретами.

Каталог после второй итерации 2026-09-09: **83 записи, 237 WebP (60 999 542 байта)**. Все первоначальные 21 и предыдущие 35 записей сохранены. The Met — 10, Cleveland Museum of Art — 9, Commons — 64 (для части есть дополнительные музейные/научные источники). Традиции: русская — 46, грузинская — 7, византийская — 21, египетская византийского времени — 1, греческая — 7, Крит/Константинополь с неопределённой атрибуцией — 1. Новое расширение: 5 грузинских, 10 синайских, 6 критских и 6 икон Кирилло-Белозерского ансамбля. Две прежние фотографии — CC BY-SA 4.0; остальные новые репродукции — PD-Art. SHA-256 и фактические URL сохранены в манифесте. Для шести новых кирилловских образов использованы сканы из научного издания на Icon-art, с соответствующими записями PD-Art на Commons. Исходники не входят в публикацию.

Число записей не равно числу самостоятельных ансамблей: три створки складня, три календарных фрагмента Ахали-Шуамта и части синайских эпистилиев описаны именно как части. Некоторые грузинские изображения имеют небольшое разрешение; масштабирование не создаёт новых деталей. Несверенные первичные атрибуции и неустановленные собрания явно оговорены.

Крупная копия вставляется в DOM только после открытия zoom. Обычные изображения используют `srcset`, `sizes` и lazy loading; первая иллюстрация получает приоритет. Zoom — нативный `dialog`, Escape, кнопки / range, прокрутка клавиатурой и пальцем, фокус возвращается к открывшей кнопке. Это увеличение производной до 1600 px, не IIIF tile viewer.

Для добавления произведения:

1. Проверить музейную запись и права именно на выбранный файл. Для Commons сохранять ссылку на страницу файла, не только на CDN. Не использовать неизвестные права, произвольные изображения из поиска или AI-замены.
2. Создать устойчивый ID, паспорт и запись индекса. Регион, традиция, атрибуция и музей — отдельные поля. Сохранять «около», «приписывается», интервалы, поновления и разную датировку частей.
3. Сохранить сведения исходной записи в `originalMetadata` (для музейных API — исходную музейную формулировку); русский материал — перевод, не новая экспертиза. Для неизвестного мастера не изобретать школу. Сведения, пересказанные через Commons, обозначать именно так.
4. Отредактировать наблюдаемые признаки, подсказки и правдоподобные, однозначные альтернативы. Для включения в главную викторину заполнить три вопроса `recognition` и `recognitionGroup`; сверить каждое объяснение именно с выбранным изображением. При необходимости задать область `recognition.detail` после визуальной проверки. Дату, автора и собрание не выдавать за факт, который можно вывести из одного визуального признака.
5. Заполнить манифест, проверить SHA-256 и подготовить WebP через `python3 scripts/iconography/prepare-images.py --cache /tmp/iconography-images` (Pillow). Скрипт останавливается при изменившемся исходнике. Исходники хранятся вне репозитория.
6. Прогнать тесты каталога и вручную сравнить изображения, заголовки и источники. Для тысяч записей хранить медиа вне Git; индекс пока рассчитан на несколько тысяч, не на неограниченный архив.

Фильтр века — навигационный ориентир. Для открытых датировок («около 1500 или позднее») перечислены начальные ориентиры; он не означает доказанной верхней границы. Для поновлений указываются века основы и видимых позднейших изменений, а не дата единого неизменного объекта.

## Обучение

Главная сразу показывает вопрос и изображение. В коллекции сначала показаны русские живописные образы из викторины; это порядок отображения, исходный индекс и все старые записи сохранены. Сравнение начинается с пары «Пётр и Павел». Нет предварительного выбора режима, рекламного hero или счётчика размера коллекции. Спокойная цветовая гамма и музейная типографика сохранены; в шапке только «Викторина» и «Коллекция». Остальные возможности раскрываются после занятия или через настройки. Декоративные стрелки и плашка поверх изображения убраны.

`RecognitionQuiz` переиспользует `Artwork`, загрузчик JSON, общий localStorage-прогресс и генератор вариантов. В `recognition` полного паспорта хранятся три независимых вопроса: начальный узнаёт персонажа/сцену («Апостол»), средний уточняет имя/тип (Пётр, Павел, Иоанн и другие), углублённый спрашивает о значимых деталях. Это изменение содержания, а не только количества вариантов. В индекс добавлен только лёгкий `recognitionGroup` для разнообразия подборки; сами вопросы остаются вне JS bundle. В текущем каталоге 65 записей включены в этот режим: 41 русская, 7 грузинских, 10 византийских, 6 греческих/критских и прежний образ Крит/Константинополь.

По умолчанию выбраны **«Средний» и «Русская традиция»**; два подписанных select постоянно видны над вопросом. Доступны отдельные русская, грузинская, византийская, греческая/критская подборки и все традиции. Занятие содержит до семи разных сюжетных групп; следующие занятия меняют примеры. Грузинское занятие содержит шесть групп из семи записей, без подмешивания русских работ. После ответа — объяснение, раскрываемые сведения и ссылка на паспорт; для 11 работ можно включить отметку визуального признака. Это отдельный SVG поверх неизменённой репродукции с нормализованными координатами, доступным названием и поддержкой адаптивного размера. Повторение сохраняет исходную сложность вопроса. Кнопка следующего шага возвращает страницу наверх, фокус — на вопрос; при показе признака изображение возвращается в область просмотра с учётом reduced motion.


11 тематик: сюжеты, персонажи, атрибуты, общие типы, отдельно типы Богородицы, праздники, традиции, периоды, атрибуции, музеи, иконостас. Режим одной иконы включает восемь вопросов и полный паспорт в конце. Занятие по параметру загружает до восьми паспортов; повторение — до 12 паспортов и 12 вопросов за раз. Текстовые занятия по праздникам и иконостасу не загружают паспорта.

В дополнительных режимах сохранены прежние три уровня помощи: два ответа с открытой подсказкой; четыре ответа с подсказкой по запросу; предварительное самостоятельное воспоминание с последующим выбором. Свободный текст на третьем уровне не оценивается AI. Ошибки сопровождаются правильным ответом и объяснением. В текущем выпуске — 664 вопроса полного паспорта, 195 вопросов главной викторины и 18 вводных вопросов.

`academy.iconography.progress.v1` в localStorage хранит счётчики и максимум 500 ID сложных вопросов. Повторная ошибка не дублирует вопрос, правильный ответ удаляет только этот ID. Неподдерживаемое/испорченное хранилище не ломает занятие; сохранение не обещается при ошибке записи. Синхронизации между устройствами нет. Икона дня определяется UTC-днём и стабильным порядком индекса; изменение порядка редактором изменит календарь.

## Обратная связь и поддержка

Единый транспорт — `src/lib/feedback.ts` → существующий callable `sendFeedback` → существующий Telegram helper/бот. Модальное окно Академии и форма портала используют один транспорт. См. [feedback-system.md](feedback-system.md).

Форма портала отправляет текст, URL и `iconId`; ID дублируется в текстовом префиксе для совместимости с ранее опубликованной функцией. Локальные защиты: honeypot, задержка, блокировка двойной отправки, минутный интервал; сервер: строгие типы/длины, honeypot, проверка URL/ID, существующий лимит 5 сообщений за 10 минут на uid/IP одного инстанса. Это не распределённая антибот-система. Публичных комментариев и базы отзывов не добавлено.

Реквизиты РФ и Грузии отсутствуют. До публикации платёжных данных нужны имя/наименование получателя, статус, назначение средств, реквизиты и подтверждение права на их публикацию. Донат не меняет доступ.

## Две сборки, один код

Обычная: `npm run build` → `dist`, портал является разделом Академии.

Отдельная: `npm run build:iconography` → `dist-iconography`. `iconography.html` / `src/iconography-main.tsx` используют ту же lazy-страницу, `PageLoader`, шрифты и восстановление прокрутки. PURE-аннотации безопасных фабрик в `pages/lazy.ts` позволяют исключить неиспользуемые страницы из отдельной сборки; общая сборка проверяется тем же build. Копируются только публичные данные портала. Курсов, админских страниц, API и тяжёлого timeline-архива в отдельном артефакте нет. Firebase Auth listener и Firestore-подписки не запускаются; существующая конфигурация Firebase используется только транспортом обратной связи.

Локальный просмотр отдельного артефакта:

```bash
npm run build:iconography
npm run preview:iconography -- --host 127.0.0.1 --port 4174 --strictPort
```

URL: `http://127.0.0.1:4174/iconography`. В обычном dev-сервере: `http://127.0.0.1:5173/iconography`.

Для отдельного Vercel Hobby публиковать именно содержимое `dist-iconography` как статический проект после одобрения. Не подключать весь корень этого репозитория как новый Hobby-сайт: он содержит коммерческие маршруты Академии и `api/`. В артефакт копируется `static-hosting.vercel.json` с явными SPA rewrites и cache headers, не перехватывающими JSON/изображения. Домены, аккаунт и автоматизацию публикации выбирает владелец перед production. Новый Firebase-проект для каталога не требуется; смена Firebase-конфигурации без сохранения общего feedback endpoint нарушит обратную связь.

Предпочтительный бюджетный вариант: отдельный личный бесплатный Vercel Hobby, изображения как статические файлы, существующий Telegram callable. Донаты сами по себе разрешены Hobby; обход квот через дополнительные аккаунты не допускается. При блокировках в РФ рассмотреть отдельный Firebase Hosting Spark как альтернативу/зеркало: это Hosting, не платное Cloud Storage. Конкретные квоты и цены — в [отчёте](../reports/iconography-local-2026-09-08.md).

## Проверки и production gate

`npm run validate:full`, `npm run typecheck:functions`, `cd functions && npm test -- --run`, `cd functions && npm run build`, отдельный build и desktop/mobile smoke. Каталог проверяется на существование всех файлов, уникальность ID, права и однозначные варианты ответов; сценарии проверяют полный паспорт, исправление сложного ответа, режим без загрузки изображений и ошибки формы.

До production нужны отдельное явное одобрение владельца, выбранный хостинг/домен и решение по тексту поддержки. Targeted Functions deploy затрагивает только `sendFeedback`; новые/удаляемые функции отсутствуют. Изменение helper с `plainText` сохраняет прежний Markdown по умолчанию для остальных функций. Push в `main` автоматически публикует Академию и запускает зеркало — до одобрения запрещён.

Подробности редизайна, источник расхождений датировок и актуальный размер архива: [актуальный локальный отчёт](../reports/iconography-update-2026-09-10.md).

## Паспорта и маршрут перед поездкой (вторая итерация 2026-09-09)

У всех 83 записей есть `reading` — проверенные через Wikipedia API ссылки о персонаже/сюжете (48 уникальных URL); это дополнительное чтение, не источник спорной атрибуции. `clues` содержат отдельные заголовки и пояснения без порядковых номеров и повторяющегося «Что важно помнить». `story` добавляет предметный контекст там, где он подтверждён. Оговорки `caution` перенесены в раскрываемый раздел источников.

`BackLink` сверху и снизу паспорта возвращает по безопасному локальному `location.state.returnTo`; прямой вход ведёт к каталогу. `IconCard` сохраняет query, страницу и якорь карточки. Переход к школе сохраняет также `returnState`: цепочка каталог → икона → школа → икона не теряет фильтры. Ссылки на школу в фактах не меняют исходную формулировку региона.

`Learn` переиспользует `Artwork` и индекс. Четыре шага: Гавриил в Деисусе, омофор Николая, Крещение, Успение. Ответ раскрывается отдельно, шаг сохраняется в query `step`; переход в паспорт возвращает к выбранному шагу. Схема относится к четырёхрядному ансамблю около 1497 года, а не ко всем восточнохристианским храмам. Исторический состав и современные места хранения разнесены; маршрут не обещает наличия всех оригиналов в храме. Общие текстовые задания по праздникам/иконостасу в `learning.ts` сохранены.
