# Иконография: бесплатный публичный портал

Статус: опубликовано в составе Академии 2026-09-11 (`academydom.com/iconography`, без ссылок с сайта); итерация «до демо» — 2026-09-11 (рандомизация, разбор ошибок, переписанный контент паспортов); итерация 2 — 2026-09-12 (темы практики по ответу, словарь сюжетов, глоссарий, повторы, сравнение, школы, мобильный ответ). Живой список замечаний — [iconography-backlog.md](../processes/iconography-backlog.md).

## Маршруты и переиспользование

`/iconography/*` — самостоятельный публичный раздел без регистрации. `src/pages/IconographyPage.tsx` загружается через `src/pages/lazy.ts` и общий `Suspense` / `PageLoader`. `AppShell` использует существующую ветку `StandaloneLandingShell`, без загрузки курсов. В общей сборке сохраняется глобальная инициализация Auth Академии; каталог и прогресс сами не обращаются к Firestore.

| Путь | Назначение |
| --- | --- |
| `/iconography` | Сразу викторина по узнаваемым храмовым образам, до семи икон за занятие |
| `/iconography/catalog` | Поиск, фильтры традиции и века, страницы по 12 записей |
| `/iconography/icon/:id` | Изображение, полный паспорт, признаки, источники, комментарий |
| `/iconography/practice` | Тренировка параметра, одного произведения, повторение |
| `/iconography/compare` | Два произведения рядом, пять подготовленных пар, произвольный выбор |
| `/iconography/learn?step=0` | Четыре наблюдения на иконах Кирилло-Белозерского иконостаса, его четырёхрядная схема |
| `/iconography/schools` | Индекс 12 статей о школах: заголовок, первая фраза, число икон коллекции |
| `/iconography/schools/:id` | Статья о школе/традиции в жанре «на что смотреть», примеры из коллекции, источники |
| `/iconography/glossary` | Глоссарий терминов; те же термины всплывают пояснением в текстах портала |
| `/iconography/about` | Принципы отбора, источники, ограничения, кто делает проект |
| `/iconography/support` | Редирект на «О проекте» до появления реквизитов (маршрут сохранён) |

Параметры URL: `q`, `tradition`, `century`, `page` в каталоге; `left`, `right` в сравнении; `icon`, `topic`, `repeat=1` в практике. Фильтры доступны по прямой ссылке. `Practice` имеет ключ по query string, чтобы переход к повторению действительно создавал новое занятие.

## Данные и расширение каталога

- `public/iconography/catalog.json` — компактный поисковый индекс, загружается только после входа в портал; не импортируется в JS.
- `public/iconography/schools.json` — 12 статей в жанре «на что смотреть»: `intro`, секции-ориентиры с `examples` (иконы коллекции и фраза, что именно смотреть), последняя секция — короткая оговорка; загружаются при входе на страницу школы. `schoolId` в индексе связывает примеры, не уточняя спорную атрибуцию.
- `public/iconography/glossary.json` — 43 термина (`id`, `term`, `forms` — словоформы для поиска в тексте, `definition`, `example` с иконой коллекции). Грузится один раз за сессию через `GlossaryProvider`; без файла портал работает как прежде. Богородичные и христологические типы (Одигитрия, Умиление, Вседержитель…) в глоссарий намеренно не входят — это ответы викторины. Правило `*sa*.json` в `.gitignore` ловило `glossary.json`, для него добавлено исключение.
- `public/iconography/records/*.json` — независимые полные паспорта и задания. Загружаются по требованию, кэш ограничен 40 записями.
- `public/iconography/images/*.webp` — 320 / 800 / 1600 пикселей по ширине, без увеличения исходников.
- `scripts/iconography/media-manifest.json` — источник, лицензия, авторство репродукции, дата проверки, SHA-256 скачанной музейной копии.
- `VITE_ICONOGRAPHY_ASSET_BASE` — необязательный базовый HTTPS-адрес каталога и медиа, по умолчанию `/iconography`. При переносе нужны CORS для JSON и та же структура файлов. Не использовать URL с секретами.

Каталог после второй итерации 2026-09-09: **83 записи, 237 WebP (60 999 542 байта)**. Все первоначальные 21 и предыдущие 35 записей сохранены. The Met — 10, Cleveland Museum of Art — 9, Commons — 64 (для части есть дополнительные музейные/научные источники). Традиции: русская — 46, грузинская — 7, византийская — 21, египетская византийского времени — 1, греческая — 7, Крит/Константинополь с неопределённой атрибуцией — 1. Новое расширение: 5 грузинских, 10 синайских, 6 критских и 6 икон Кирилло-Белозерского ансамбля. Две прежние фотографии — CC BY-SA 4.0; остальные новые репродукции — PD-Art. SHA-256 и фактические URL сохранены в манифесте. Для шести новых кирилловских образов использованы сканы из научного издания на Icon-art, с соответствующими записями PD-Art на Commons. Исходники не входят в публикацию.

Число записей не равно числу самостоятельных ансамблей: три створки складня, три календарных фрагмента Ахали-Шуамта и части синайских эпистилиев описаны именно как части. Некоторые грузинские изображения имеют небольшое разрешение; масштабирование не создаёт новых деталей. Несверенные первичные атрибуции и неустановленные собрания явно оговорены.

Крупная копия вставляется в DOM только после открытия zoom. Обычные изображения используют `srcset`, `sizes` и lazy loading; первая иллюстрация получает приоритет. Zoom — нативный `dialog` с `role`, `aria-modal` и названием иконы, непрозрачный фон, Escape (подсказка о нём только при `hover: hover`), кнопки / range, прокрутка клавиатурой и пальцем, фокус возвращается к открывшей кнопке. В паспорте «На что обратить внимание» стоит выше таблицы фактов; на телефоне сравнение показывает иконы по одной в ряд. Это увеличение производной до 1600 px, не IIIF tile viewer.

Для добавления произведения:

1. Проверить музейную запись и права именно на выбранный файл. Для Commons сохранять ссылку на страницу файла, не только на CDN. Не использовать неизвестные права, произвольные изображения из поиска или AI-замены.
2. Создать устойчивый ID, паспорт и запись индекса. Регион, традиция, атрибуция и музей — отдельные поля. Сохранять «около», «приписывается», интервалы, поновления и разную датировку частей.
3. Сохранить сведения исходной записи в `originalMetadata` (для музейных API — исходную музейную формулировку); русский материал — перевод, не новая экспертиза. Для неизвестного мастера не изобретать школу. Сведения, пересказанные через Commons, обозначать именно так.
4. Отредактировать наблюдаемые признаки, подсказки и правдоподобные, однозначные альтернативы. Для включения в главную викторину заполнить три вопроса `recognition` и `recognitionGroup`; сверить каждое объяснение именно с выбранным изображением. При необходимости задать область `recognition.detail` после визуальной проверки. Дату, автора и собрание не выдавать за факт, который можно вывести из одного визуального признака.
5. Заполнить манифест, проверить SHA-256 и подготовить WebP через `python3 scripts/iconography/prepare-images.py --cache /tmp/iconography-images` (Pillow). Скрипт останавливается при изменившемся исходнике. Исходники хранятся вне репозитория.
6. Прогнать тесты каталога и вручную сравнить изображения, заголовки и источники. Для тысяч записей хранить медиа вне Git; индекс пока рассчитан на несколько тысяч, не на неограниченный архив.

Фильтр века — навигационный ориентир. Для открытых датировок («около 1500 или позднее») перечислены начальные ориентиры; он не означает доказанной верхней границы. Для поновлений указываются века основы и видимых позднейших изменений, а не дата единого неизменного объекта.

## Обучение

Главная сразу показывает вопрос и изображение. В коллекции порядок по умолчанию — по векам (селект «Порядок»: по векам / по названию); фильтры — традиция (4 группы: русская, византийская, греческая, грузинская), век римскими цифрами и сюжет; поиск ранжирует совпадение по названию выше сюжета/персонажей, а те — выше тегов и музея. Редакторские пометки в `period` не показываются в карточках: если период не похож на дату, выводится век из `centuries` или «Датировка уточняется». Сравнение начинается с пары «Пётр и Павел»; при одном параметре `left` правая икона подбирается из той же `recognitionGroup` (предпочтительно другой традиции), иначе той же традиции и сюжета (`lib/compare.ts`). Пять пресетов сохраняют ручной разбор; для любой другой пары «Показать разбор» открывает автоматическое сопоставление по паспортам с честным надзаголовком: таблица «Что сравнить» (сюжет, тип, персонажи, традиция и век, материал; совпадения помечены), задание под пару («Один сюжет…», «Один тип…», «Разные образы…») и по одному наблюдению под каждой иконой, выбранному по общим значимым словам в `clues`. Наблюдения появляются только после «Показать разбор», чтобы сначала смотрели сами. Нет предварительного выбора режима, рекламного hero или счётчика размера коллекции. Спокойная цветовая гамма и музейная типографика сохранены; в шапке шесть пунктов: «Викторина», «Коллекция», «Практика», «Маршрут», «Сравнение», «Школы» (на 390 px помещаются в одну строку, на 320 px переносятся в две); «О проекте» и «Глоссарий» — в подвале. Статья о школе показывает под каждой секцией-ориентиром миниатюры примеров из коллекции с фразой «что смотреть» и ссылкой в паспорт (возврат «Назад к школе»); список других школ — обычный раздел внизу. Ссылка «Поддержать» из подвала убрана до появления реквизитов, `/support` редиректит на «О проекте». Декоративные стрелки и плашка поверх изображения убраны. Счётчики в фильтре «Сюжет» считаются по текущему срезу традиции и века; значения `subject` — из словаря канонических сюжетов ([quiz-design](iconography-quiz-design.md)), так что фильтр показывает те же слова, которым учит викторина. Несуществующий id паспорта отвечает «Такой иконы нет» со ссылкой на коллекцию; сетевая ошибка — прежним текстом с «Повторить».

Термины из глоссария в подсказках, объяснениях, разборах дистракторов, `description`/`clues`/`story`/`caution` паспорта, шагах маршрута, статьях о школах и разборах сравнения размечаются компонентом `WithGlossary` (`lib/glossary.ts` → `markTerms`: границы слова по буквам Unicode, ё=е, самая длинная форма первой, только первое вхождение термина в тексте): пунктирное подчёркивание, на десктопе пояснение по наведению и фокусу, на телефоне по тапу, Escape закрывает, ссылка «В глоссарии →» ведёт на `/iconography/glossary#<id>`. Варианты ответов, заголовки и поля фактов не размечаются. `RecognitionQuiz` переиспользует `Artwork`, загрузчик JSON, общий localStorage-прогресс и генератор вариантов. Правила контента (три разных уровня, `rationale` для каждого дистрактора, подсказка без ответа, только визуальные темы в практике) — в [iconography-quiz-design.md](iconography-quiz-design.md); гейт `npm run check:iconography` (`scripts/iconography/validate-records.cjs`) входит в `npm run validate`. Индекс `catalog.json` пересобирается из паспортов скриптом `scripts/iconography/sync-catalog.cjs` — вручную его не правят. В `recognition` полного паспорта хранятся три независимых вопроса: начальный узнаёт персонажа/сцену («Апостол»), средний уточняет имя/тип (Пётр, Павел, Иоанн и другие), углублённый спрашивает о значимых деталях. Это изменение содержания, а не только количества вариантов. В индекс добавлен только лёгкий `recognitionGroup` для разнообразия подборки; сами вопросы остаются вне JS bundle. В викторину включены все 83 записи (с 2026-09-11; до этого 65 — записи Met и Кливленда не участвовали).

По умолчанию выбраны **«Средний» и «Русская традиция»**; два подписанных select постоянно видны над вопросом. Доступны отдельные русская, грузинская, византийская, греческая/критская подборки и все традиции. Занятие содержит до семи разных сюжетных групп. Подборка случайна: сид на занятие, группы и работа внутри группы перемешиваются; иконы трёх последних занятий исключаются (`academy.iconography.lastLessons.v2`), а внутри группы предпочитается реже виденная работа (счётчик показов `academy.iconography.seen.v1`); порядок вариантов ответа перемешивается на каждое занятие и на каждый повтор. «Все традиции» набирает группы круговым обходом традиций, поэтому русских икон в занятии не больше двух. Для подборок из семи икон (грузинская, греческая) над вопросом и на итоге стоит честная пометка «в подборке всего 7 икон — повторы неизбежны» с кнопкой «Все традиции»; репродукции уже 400 px показываются в натуральную величину с подписью «Небольшая репродукция». После ответа — при ошибке заголовок «Неверно», разбор именно выбранного варианта (`rationale`), затем «Верный ответ: «…»» и объяснение уровня; при верном ответе — «Верно» и объяснение; страница подводит разбор в экран, на телефоне тоже. Дальше раскрываемые сведения и ссылка на паспорт; там, где задан `recognition.detail`, на **углублённом** уровне можно включить отметку визуального признака (рамка написана под углублённый вопрос, на других уровнях кнопки нет); при показе изображение возвращается в область просмотра после отрисовки SVG. Это отдельный SVG поверх неизменённой репродукции с нормализованными координатами, доступным названием и поддержкой адаптивного размера. Итог занятия: «Верно N из M», список икон с пометкой верно/неверно, выбранным и верным ответом и ссылкой на паспорт; кнопки «Ещё иконы», «Повторить ошибки этого занятия» (только ошибки сессии) и «Повторить сложное» (накопленные); накопительный счётчик со склонением («3 вопроса») и кнопка «Сбросить прогресс» с подтверждением (чистит прогресс, историю занятий и счётчик показов). Переход на следующий уровень — явная кнопка «Начать углублённое занятие». Повторение сохраняет исходную сложность вопроса. Перед первым вопросом — вводный блок (честно: три варианта на начальном, четыре на остальных) и раскрывашка «Как устроены уровни»; смена уровня или традиции во время занятия требует подтверждения (тихого сброса нет). Кнопка следующего шага возвращает страницу наверх, фокус — на вопрос; при показе признака изображение возвращается в область просмотра с учётом reduced motion.


9 тем: сюжеты, персонажи, атрибуты и жесты, иконографические типы, типы Богородицы, праздники, композиция и формат, материал и техника, иконостас. Тема вопроса определяется его ответом (таблица тем в [quiz-design](iconography-quiz-design.md)); над вопросом стоит название темы. Пул темы — вопросы `questions` **и** три вопроса `recognition` каждого паспорта с этой темой, поэтому «Сюжеты», «Типы» и «Типы Богородицы» наполняются в основном вопросами среднего уровня викторины; «Типы Богородицы» берёт иконы по `recognitionGroup === 'mary'`. Темы «традиции», «периоды», «атрибуции», «музеи» убраны: это факты паспорта, а не то, что можно увидеть. Режим одной иконы = 3–5 визуальных вопросов паспорта + углублённый вопрос викторины, без дублей формулировок, полный паспорт в конце; списки икон в «Одной иконе» и «Сравнении» сгруппированы по традиции и отсортированы по названию. Занятие по параметру загружает до восьми паспортов (для «Праздников» — по праздничным `recognitionGroup`); повторение — до 12 вопросов, уровень вопроса викторины берётся из его id, вопросы практики повторяются на среднем. Текстовые карточки `learning.ts` остались только в «Иконостасе» и «Праздниках». Пустая тема показывает «Вопросов по этой теме пока нет». Ссылка под вопросом — «Источник изображения». На итоге один список произведений занятия с пометкой ошибок.

Уровни практики называются так же, как в викторине: Начальный (три варианта, подсказка открыта), Средний (четыре варианта, подсказка по запросу), Углублённый (сначала вспомнить, затем открыть варианты; поля свободного ввода нет). Ошибки сопровождаются разбором выбранного варианта, верным ответом и объяснением; в итоге — счёт и список ошибок. Порядок вопросов и вариантов перемешивается по сиду занятия.

`academy.iconography.progress.v1` в localStorage хранит счётчики и максимум 500 ID сложных вопросов. Повторная ошибка не дублирует вопрос, правильный ответ удаляет только этот ID. Неподдерживаемое/испорченное хранилище не ломает занятие; сохранение не обещается при ошибке записи. Синхронизации между устройствами нет. Икона дня определяется UTC-днём и стабильным порядком индекса; изменение порядка редактором изменит календарь.

## Обратная связь и поддержка

Единый транспорт — `src/lib/feedback.ts` → существующий callable `sendFeedback` → существующий Telegram helper/бот. Модальное окно Академии и форма портала используют один транспорт. См. [feedback-system.md](feedback-system.md).

Форма портала отправляет текст, URL и `iconId`; ID дублируется в текстовом префиксе для совместимости с ранее опубликованной функцией. Локальные защиты: honeypot, задержка, блокировка двойной отправки, минутный интервал; сервер: строгие типы/длины, honeypot, проверка URL/ID, существующий лимит 5 сообщений за 10 минут на uid/IP одного инстанса. Это не распределённая антибот-система. Публичных комментариев и базы отзывов не добавлено.

Реквизиты РФ и Грузии отсутствуют. До публикации платёжных данных нужны имя/наименование получателя, статус, назначение средств, реквизиты и подтверждение права на их публикацию. Донат не меняет доступ.

## Две сборки, один код

Обычная: `npm run build` → `dist`, портал является разделом Академии.

Отдельная: `npm run build:iconography` → `dist-iconography`. `iconography.html` / `src/iconography-main.tsx` используют ту же lazy-страницу, `PageLoader`, шрифты и восстановление прокрутки. PURE-аннотации безопасных фабрик в `pages/lazy.ts` позволяют исключить неиспользуемые страницы из отдельной сборки; общая сборка проверяется тем же build. Копируются только публичные данные портала. Курсов, админских страниц, API и тяжёлого timeline-архива в отдельном артефакте нет. Firebase Auth listener и Firestore-подписки не запускаются; существующая конфигурация Firebase используется только транспортом обратной связи.

Локальный просмотр отдельного артефакта:

```bash
npm run build:iconography
npm run preview:iconography -- --host 127.0.0.1 --port 4174 --strictPort
```

URL: `http://127.0.0.1:4174/iconography`. В обычном dev-сервере: `http://127.0.0.1:5173/iconography`.

Для отдельного Vercel Hobby публиковать именно содержимое `dist-iconography` как статический проект после одобрения. Не подключать весь корень этого репозитория как новый Hobby-сайт: он содержит коммерческие маршруты Академии и `api/`. В артефакт копируется `static-hosting.vercel.json` с явными SPA rewrites и cache headers, не перехватывающими JSON/изображения. Домены, аккаунт и автоматизацию публикации выбирает владелец перед production. Новый Firebase-проект для каталога не требуется; смена Firebase-конфигурации без сохранения общего feedback endpoint нарушит обратную связь.

Предпочтительный бюджетный вариант: отдельный личный бесплатный Vercel Hobby, изображения как статические файлы, существующий Telegram callable. Донаты сами по себе разрешены Hobby; обход квот через дополнительные аккаунты не допускается. При блокировках в РФ рассмотреть отдельный Firebase Hosting Spark как альтернативу/зеркало: это Hosting, не платное Cloud Storage. Конкретные квоты и цены — в [отчёте](../reports/iconography-local-2026-09-08.md).

## Проверки и production gate

`npm run validate:full`, `npm run typecheck:functions`, `cd functions && npm test -- --run`, `cd functions && npm run build`, отдельный build и desktop/mobile smoke. Каталог проверяется на существование всех файлов, уникальность ID, права и однозначные варианты ответов; сценарии проверяют полный паспорт, исправление сложного ответа, режим без загрузки изображений и ошибки формы.

До production нужны отдельное явное одобрение владельца, выбранный хостинг/домен и решение по тексту поддержки. Targeted Functions deploy затрагивает только `sendFeedback`; новые/удаляемые функции отсутствуют. Изменение helper с `plainText` сохраняет прежний Markdown по умолчанию для остальных функций. Push в `main` автоматически публикует Академию и запускает зеркало — до одобрения запрещён.

Подробности редизайна, источник расхождений датировок и актуальный размер архива: [актуальный локальный отчёт](../reports/iconography-update-2026-09-10.md).
