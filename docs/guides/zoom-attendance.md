# Посещаемость Zoom

Первый автоматический маршрут: Server-to-Server OAuth для аккаунтов
владельца, периодический импорт отчётов и ручная привязка участников к студентам.
Развёрнут 2026-11-03: шесть новых Cloud Functions, Firestore rules и интерфейс.
CSV-импорт и OAuth-подключение внешних авторов в этот этап не входят.

**Подключение проверено 2026-11-03:** в аккаунте владельца создано и
активировано `DOM Academy Attendance` с тремя read-only scopes ниже. Credentials
сохранены в Secret Manager; appspot service account получил `secretAccessor`
только на `zoom-attendance-accounts`, read-back секрета совпал. Пробный запрос
по событию группы «Психология развития 2026» за 31 октября успешно вернул
39 подключений, у всех есть время входа/выхода; UUID сессии совпал. Email и
стабильный Zoom ID есть только у одной строки, поэтому остальные подключения
пока требуют ручной привязки в отчёте, без сохранения по имени на будущее.
Подключена **только «Психология развития 2026»**, аккаунт `primary`, порог 50%.
В production Firestore сохранены полные отчёты 29 октября (84 строки подключений
в пределах занятия) и 31 октября (37 строк из 39 исходных подключений).
Это строки подключений, а не число людей. Отчёт 31 октября повторно сверён с
Zoom: все сохранённые строки и интервалы точно совпали с `buildRows`.
Cloud Scheduler включён каждые 30 минут; запуск через Scheduler успешно
импортировал 29 октября, обновил `lastPolledAtMs`; готовый отчёт 31-го сохранён.
В группе на дату проверки 3 зарегистрированных активных студента, pending нет.

## Как пользоваться

В `/admin/announcements` выберите конкретную несистемную группу. В блоке
«Посещаемость Zoom» super-admin выбирает настроенный аккаунт и порог зачёта
(целое число 1–100%, по умолчанию 50%). Отключение учёта сохраняет данные.
Обычный админ видит отчёт и может привязывать участников только в группах,
где он назначен в `announcementAdminIds`. Co-admin сам по себе доступа не даёт.

Для импорта событие должно иметь `kind: event`, `startAt`, `endAt` и обычную
HTTPS Zoom-ссылку с числовым meeting ID (`/j/...` или `/wc/...`). События на
весь день, задания, vanity-ссылки и интервалы больше суток не импортируются.
Если ссылка или время изменились, старый отчёт не показывается под новым занятием.

Выберите завершившееся занятие, чтобы увидеть минуты, процент и зачёт по
студентам, а также исходных участников. «Синхронизировать» запускает импорт
после 30 минут с конца занятия; повторный запуск одного отчёта — не чаще
раза в 10 минут. «Обновить» перечитывает уже сохранённые данные.
Отчёты ещё в обработке показывают ожидание, а не отсутствие студентов.
Над таблицей указано количество непривязанных подключений: до сопоставления
минуты студентов могут быть неполными. У студента готовый отчёт с нулём
распознанных минут показывает «Присутствие пока не подтверждено» и просьбу
обратиться к преподавателю; положительные минуты ниже порога — «Не зачтено».

На `/home` студент открывает событие своей группы и видит только свою
посещаемость. Списки участников, чужие минуты и email студентам не возвращаются.
Это отображение в карточке события; отдельной сводной таблицы всех занятий
в профиле на этом этапе нет.

## Подключение собственного аккаунта

Используется **Server-to-Server OAuth**, а не Google-токен входа пользователя.
Вход Google в кабинет Zoom нужен только для настройки приложения.

1. В Zoom Marketplace откройте Created apps → Add → Build app. Если Zoom
   требует принять API License / Terms of Use, соглашение принимает владелец
   либо агент после отдельного явного подтверждения действия.
2. Создайте внутреннее Server-to-Server OAuth приложение. Достаточны три
   granular scopes (все read-only):
   - `meeting:read:list_past_instances:admin`;
   - `report:read:meeting:admin`;
   - `report:read:list_meeting_participants:admin`.
3. Заполните обязательную информацию и активируйте приложение. Нужен Pro+
   аккаунт и права владельца/администратора для этого типа приложения.
4. Поместите credentials в Secret Manager проекта `psych-dev-site-prod`,
   secret **`zoom-attendance-accounts`**, с таким JSON-контрактом:

   ```json
   {
     "accounts": [{
       "key": "primary",
       "label": "Основной Zoom",
       "accountId": "<Account ID>",
       "clientId": "<Client ID>",
       "clientSecret": "<Client Secret>"
     }]
   }
   ```

   `key` — уникальный slug `[a-z0-9-]` до 40 символов. До 20 аккаунтов.
   Секреты не класть в Git, клиентские env, пользовательские документы или чат.
   Чтение — через существующий `readLatestSecretValue`; service account
   `psych-dev-site-prod@appspot.gserviceaccount.com` должен иметь доступ к этому
   секрету. Кеш конфигурации живёт 5 минут, токен — до срока истечения с запасом.
5. После явного согласования выполнить targeted deploy **только новых** функций:
   `getZoomAttendance`, `setZoomAttendanceConnection`, `syncZoomAttendance`,
   `matchZoomAttendanceParticipant`, `getMyZoomAttendance`, `pollZoomAttendance`.
   Существующие функции не заменяются и не удаляются. Rules добавляют явный
   рекурсивный запрет для новой серверной коллекции; перед rules deploy
   обязательны integration tests. Frontend публикуется отдельно через Vercel.
6. Выбрать группу и аккаунт на сайте. Сделать пробный импорт прошедшего занятия,
   проверить реальный формат имён/email, повторные входы и сопоставление UUID.
   До этой проверки фактическое получение production-отчёта не подтверждено.

Первичное создание приложения/его активация расширяют серверный доступ к
отчётам Zoom; это отдельное внешнее действие. Локальные тесты не дают на него
автоматического разрешения.

Официальные источники (сверены 2026-11-03):
[Server-to-Server OAuth](https://developers.zoom.us/docs/internal-apps/),
[Meetings API](https://developers.zoom.us/docs/api/meetings/).
Zoom может скрыть email внешних участников даже при входе под аккаунтом.

## Импорт и расчёт

`pollZoomAttendance` работает каждые 30 минут в `us-central1`. Выбирает события
последних 7 суток; готовые отчёты повторно проверяет не чаще раза в 6 часов
в первые сутки после занятия. Неполные отчёты/ошибки повторяются после задержки
не менее 30 минут, с учётом `Retry-After`. Старые готовые отчёты автоматически
не перегружаются. Ручной импорт и админский список ограничены последними
30 сутками и 60 Zoom-событиями (читаются максимум 200 событий по `startAt`).

Meeting ID постоянной ссылки не используется как идентификатор занятия.
По нему запрашивается список прошедших **UUID сессий**, затем выбираются
сессии, начавшиеся не раньше чем за 30 минут до планового начала и до конца
занятия. Перезапуски в этом окне объединяются. Если одна сессия подходит
двум событиям одной группы, импорт просит уточнить время и не угадывает.
Стартовавшую более чем за 30 минут до занятия встречу нужно отразить в календаре.

Используются все страницы отчёта подключений, с проверками формата, таймаутом
20 секунд на запрос и однократным обновлением токена после HTTP 401.
Лимиты: 100 страниц/10 000 подключений на сессию, 8 сессий и 2000 объединённых
участников на занятие. Превышение не публикует частичный результат.

Время — пересечение `join_time`/`leave_time` с плановым интервалом занятия.
Ожидание в waiting room не считается. Пересекающиеся подключения одного
студента, включая несколько устройств, объединяются: минута считается один
раз. Процент считается от плановой длительности; порог проверяется **до**
округления минут и процентов для UI.

Идентификация:

- Совпадающий email Zoom и **подтверждённый email Firebase Auth** участника
  группы сопоставляются автоматически. Редактируемый `users.email` для этого
  не используется. Pending-приглашения и отключённые Auth-пользователи не
  входят в таблицу до регистрации/включения.
- Админ выбирает студента вручную. «Запомнить» сохраняет привязку стабильного
  `participant_user_id` (fallback `id`) или email, только внутри этой группы
  и этого аккаунта. Повторное имя само по себе не считается совпадением.
- Если стабильного ID/email нет, можно привязать подключение только к текущему
  занятию. Одноимённые гости не склеиваются. Переход на другой Zoom-профиль
  потребует новой привязки.
- Ручная отвязка блокирует автоматическое совпадение в этом отчёте.
  Перепривязка к отсутствующему в группе студенту не возвращает его минуты
  другому участнику по email.

Импорт берёт lease на занятие. Новые строки пишутся в отдельный snapshot;
указатель `activeSnapshot` меняется только после полного завершения записи.
Ошибка обновления оставляет предыдущий полный отчёт. Snapshot и ручные
привязки разделены, поэтому повторный импорт не перезаписывает ручной выбор.
Предыдущие snapshots сохраняются для проверки; автоматического удаления нет.

## Хранилище и доступ

`zoomAttendanceGroups/{groupId}` — настройки и состояние опроса.
Подколлекции `sessions/{eventId}`, `aliases/{hash}`; у сессии —
`snapshots/{snapshotId}/participants/{key}` и `overrides/{key}`.
Подробная схема — [firestore-schema.md](../reference/firestore-schema.md).

Всё дерево закрыто Firestore rules даже для super-admin. Только Admin SDK
через callable-функции проверяет группу и возвращает разрешённый контракт.
Credential/token/сырые Zoom ID в клиентский контракт не входят. Сетевые
ошибки не логируются и не возвращаются целиком; UI получает безопасное сообщение.
`accountKey` и label — публичные метки, а не credentials.

В Functions-эмуляторе `loadAccounts()` возвращает пустой список: ролевой
стенд не читает production Secret Manager и не обращается к Zoom. Для smoke
можно засидить синтетические настройки/полный snapshot через Admin SDK.

## Проверки и границы

Unit tests: `functions/src/zoomAttendance/*.test.ts`, UI tests:
`src/features/zoomAttendance/attendance.test.tsx`. Rules-регрессия:
`tests/integration/firestoreRules.test.ts`. Повторный импорт, неполные ответы,
ошибки записи, чужие группы и выдача только собственного результата проверяются
отдельно. Реальный Zoom и настройка доступа к секрету требуют отдельной
проверки после подключения; mock-тесты их не подменяют.
